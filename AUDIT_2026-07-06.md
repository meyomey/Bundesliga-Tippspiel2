## 2. Während des Audits direkt behoben

### 2.1 `build_vendor.bat`: kaputter Manifest-Pfad

Im Batch-Skript war im Pfad zu `vendor_manifest.txt` ein Steuerzeichen statt eines normalen Backslashs enthalten:

```txt
vendor\x0bendor_manifest.txt
```

Das hätte beim Vendor-Build auf Windows zu einem falschen Dateinamen bzw. fehlerhaften Manifest führen können.

**Behoben in:**

```txt
build_vendor.bat
```

Jetzt korrekt:

```bat
) > vendor\vendor_manifest.txt
```

### 2.2 Login-Seite: Standard-Admin-Hinweis produktionssicherer

Die Login-Seite zeigte bisher immer den Standard-Admin-Hinweis `admin123`. Das ist für Entwicklung praktisch, in Produktion aber unschön.

**Behoben in:**

```txt
templates/auth/login.html
```

Der Hinweis wird jetzt nur noch gezeigt, wenn:

- `ADMIN_PASSWORD == admin123`
- `REQUIRE_SECURE_CONFIG` nicht aktiv ist
- `APP_ENV` nicht `production` ist

## 4. Architektur & Wartbarkeit

### Positiv

- App-Factory vorhanden.
- Blueprints für Main/Auth/Admin/API/Push/PWA/Cache/Live vorhanden.
- Viele Admin- und Main-Bereiche wurden bereits aus den großen Ursprungsdateien ausgelagert.
- Fachlogik für Scoring, Stats, Sync, Maintenance, Awards usw. ist getrennt.
- Dokumentation ist inzwischen wieder aktuell.

### Wichtigste technische Schuld

#### 4.1 Lazy-Wrapper und `from routes_main import *`

Mehrere ausgelagerte Main-Module importieren über:

```python
from routes_main import *
```

Das funktioniert grundsätzlich, ist aber fragil. Der Saisonbericht-Fehler entstand genau dadurch: Namen mit führendem Unterstrich werden bei `import *` nicht importiert.

**Risiko:** mittelhoch  
**Empfehlung:** langfristig Helper/Fachlogik aus `routes_main.py` in saubere Service-/Helper-Dateien verschieben und explizit importieren.

Beispiel-Zielstruktur:

```txt
services/profile_stats.py
services/season_report.py
services/navigation.py
```

#### 4.2 Sehr große Module bleiben übrig

Größte Dateien:

```txt
sync.py             ca. 1139 Zeilen
routes_admin.py      ca. 918 Zeilen
stats.py             ca. 797 Zeilen
scoring.py           ca. 584 Zeilen
ai_opponent.py       ca. 523 Zeilen
```

Das ist aktuell nicht kritisch, aber langfristig fehleranfällig.

**Empfehlung:** nur bei ohnehin anstehenden Arbeiten weiter aufteilen, nicht als reines Refactoring-Projekt erzwingen.

## 5. Security-Audit

### Positiv

- Passwort-Hashes über Werkzeug.
- CSRF global aktiv.
- Tipp-Autosave sendet CSRF-Token.
- Rate Limiting über Flask-Limiter mit Fallback.
- Production-Sicherheitsgate vorhanden:
  - Default-`SECRET_KEY` wird in Production blockiert.
  - Admin-Konto mit `admin123` wird in Production blockiert.
- Wartungscenter prüft reale Admin-Hashes, nicht nur Config-Werte.
- Kommentare werden mit Bleach bereinigt.
- Mail-Passwort wird nicht im Adminformular vorausgefüllt.
- Telegram Webhook Secret wird unterstützt.

### Behoben im Audit

- Standard-Admin-Hinweis auf Login-Seite wird in Production/secure mode nicht mehr angezeigt.

### Empfehlungen für Produktion

In Netcup/Plesk unbedingt setzen bzw. prüfen:

```txt
SECRET_KEY=<langer Zufallswert>
ADMIN_PASSWORD=<sicheres Passwort>
PUBLIC_BASE_URL=https://deine-domain.de
REQUIRE_SECURE_CONFIG=1
TELEGRAM_WEBHOOK_SECRET=<zufallswert>, falls Telegram aktiv
```

### Hinweis

`app.run(debug=True)` steht nur im lokalen `if __name__ == "__main__"`-Block. Bei Plesk/Passenger wird die App importiert, daher ist das für den Server normalerweise nicht aktiv. Trotzdem sollte lokal/produktiver Direktstart nicht über `python app.py` erfolgen.

## 12. Priorisierte Empfehlungen

### Hoch

1. **Bei jedem Bugfix Regressionstest ergänzen.**  
   Hat beim Saisonbericht direkt geholfen.

2. **`from routes_main import *` schrittweise abbauen.**  
   Nicht sofort alles refactoren, aber bei betroffenen Bereichen explizite Imports/Services nutzen.

3. **Sync-Änderungen immer mit API-Mocks testen.**  
   Sync ist einer der größten Risiko-Bereiche.

### Mittel

4. **PDF/Export gezielter testen.**  
   Gerade weil User PDFs herunterladen können.

5. **Profil-/Notification-Flows besser testen.**  
   Dort steckt viel User-Konfiguration.

6. **Tipp-Detail/Schnelltipp weiter anhand Smartphone-Feedback optimieren.**

### Niedrig

7. **Große Module nur bei Bedarf weiter aufteilen.**

8. **Optional einfache Smoke-Tests für zentrale Seiten ergänzen:**
